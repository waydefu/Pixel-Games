# 2026-11-05｜HD-2D 視覺差距審查與後續技術規劃（提案）

> **文件狀態：規劃提案，尚未實作。** 審查基準為 `main` commit `63837d9`（PR #10 合併後）。本文只描述當時程式與畫面的觀察及建議路線；後續 PR 實作後，以當時程式、CI 與 Owner 決策為準，本文保留為歷史紀錄，不直接刪除。

## 0. 審查方法與證據邊界

- 逐檔閱讀 `src/game/`、`src/rendering/` 與現行文件。
- 以 `npm run build` + `vite preview` 啟動，使用 Playwright Chromium（SwiftShader 軟體 GL）截取斜角／第一人稱／風景三種視角各一張。SwiftShader 的色彩與效能**不代表真 GPU**，截圖未入庫，可用相同流程重現。
- 參考作品：[The Bells of Evermere](https://lumina-static-584822.gitlab.io/game.html?campaign=bells-of-evermere) 的標題畫面與開場畫面（僅觀察，不擷取素材入庫）。
- Owner 提供的羅弗敦（Reine 一帶）峽灣照片四張：**只作地形、配色與構圖參考**。部分照片帶有圖庫浮水印，不得作為貼圖或任何素材來源；照片中的現代漁船、公路與車輛不符合中世紀設定，不採用。
- 本文所有「px/單位」數據是由程式參數推算，不是畫面量測。

## 1. 結論

與參考作品的差距主要不在建模數量，而在三點：

1. **沒有後製層。** Evermere 的「縮微模型」質感大多來自移軸景深、窗光泛光、色調分級、暗角、顆粒與粒子；本專案目前沒有任何後製（`quality.js` 的 high 宣告 `postprocess:true`，但 `main.ts` 未建立任何後製管線，與 [INDEPENDENT-AUDIT-2026-11-05](INDEPENDENT-AUDIT-2026-11-05.md) C-8 一致）。
2. **世界邊緣破洞。** 風景模式可見矩形海面與背後空白背景，山腳與水面沒有接合。
3. **貼圖密度不一致。** 各表面的像素大小不同、部分方向被拉伸，削弱「同一套美術」的觀感。

建議順序：**先把現有畫面修正確 → 再加 HD-2D 特徵後製 → 最後才擴充內容。** NPC、新區域等玩法擴充應排在後面，並依 [ROADMAP](../ROADMAP.md) 另行授權。

## 3. HD-2D 特徵效果：建議做法

### 3.1 後製管線

順序：場景 → 泛光（僅抓窗光、燭光、陽光反射等高亮）→ 移軸景深（半解析度）→ 單次合成（色調映射、3D LUT 色調分級、暗角、輕微顆粒）。

- 加入後製後，`renderer.toneMapping` 只在直接輸出到畫面時生效，色調映射需移到最後合成階段，避免重複或遺漏。
- 畫質分級建議：
  - **basic**：不做後製。
  - **balanced**：色調分級 + 暗角 + 半解析度泛光。
  - **high**：再加上移軸景深與光束。
- **技術路線（需先實驗）：**
  - **A. 維持 WebGL2 + pmndrs `postprocessing`。** 可把多個效果合併成一個全螢幕 pass，手機比 Three 內建 EffectComposer 省；需先確認與 three 0.187 的版本相容性。
  - **B. 改用 WebGPURenderer + TSL 節點後製。** 目前只有兩支 GLSL shader（海、天空），是改寫成本最低的時間點。
  - **建議**：先做 1～2 天的技術小實驗（不合併進遊戲），在 POCO F8 Ultra 與 iPhone 實測同一場景。若 B 效能相當，就在寫更多 GLSL 之前遷移；否則採 A。`renderer-port.js` 已支援 `renderAsync()`，兩條路都不需重寫 Renderer Port 契約。

### 3.2 移軸景深（HD-2D 最關鍵的特徵）

- 以深度計算模糊半徑，焦平面對準玩家所在高度，畫面上下緣最模糊。
- 正交鏡頭可直接使用深度緩衝；另可 A/B 比較「窄 FOV（約 20°）透視鏡頭」，縮微感與景深層次更強。
- 斜角正交視角是 Owner 指定（ADR-0003），**只做比較，不直接取代**。

### 3.3 光源

- 窗光、燭光：發光材質 + 泛光；燭火以低頻雜訊微幅閃動。
- 地面光暈用貼花（加法混合的貼圖平面）製作，不大量使用 PointLight（手機成本過高）。符合 AGENTS「日光、燭光、壁燈、窗光」與禁止現代燈柱的規定。
- 樹隙、窗口的光束：用柔邊漸層平面 + 浮塵粒子做假體積光；風景／第一人稱可另做螢幕空間 god rays（僅 high）。
- 接地陰影：在合批階段烘焙頂點 AO，或在建築與道具底部放接觸陰影貼花；SSAO 只考慮 high。

### 3.4 角色精靈

- 加一個朝向太陽的陰影投射平面，使用帶 `alphaTest` 的 `customDepthMaterial`，投出剪影陰影，取代現行圓形陰影（目前因 billboard 矩形會投出方形陰影而關閉 `castShadow`）。
- 1px 暗色輪廓與依太陽方向的逆光邊緣光；走路時揚起腳步塵土粒子；待機呼吸動畫。
- 角色像素密度須與環境貼圖密度一致（見第 2 節的 32 px/單位標準）。

### 3.5 被建築遮擋時

在共用材質 shader 中，把「玩家螢幕位置附近、且位於玩家與鏡頭之間」的片段以網點（dither）挖空。不需拆開已合批的幾何，與 `batch.ts` 相容，也避開半透明排序問題。

### 3.6 環境動態

- **風**：全域風 uniform 同時驅動草（InstancedMesh vertex shader）、船帆、樹冠與炊煙方向。
- **雲影**：地面疊加緩慢移動的雜訊貼圖（乘法混合），成本低、效果明顯。
- **粒子**：炊煙、浮塵、落葉、浪花水霧；群飛海鷗精靈。

### 3.7 時段系統

把太陽方向／顏色、天空與地面環境光、霧色、LUT、窗光強度收進同一個「天空狀態」，以關鍵幀內插。預設維持黃昏。

### 3.8 效能策略

- 太陽不動時關閉陰影自動更新（`shadowMap.autoUpdate=false`），只在玩家移動超過門檻或太陽改變時才重算。
- 程序材質集中到 `DataArrayTexture`，配合世界座標 UV，讓靜態建築共用單一材質並合批，把目前約 200 個 draw call 大幅降低，預算留給後製。

## 4. 峽灣：從羅弗敦參考照片學什麼

1. **山直接從水中升起。** 上半部是灰色花崗岩峭壁，綠苔只在下緣緩坡與岩棚，雪只留在溝槽。
   - 做法：在 shader 依坡度切換材質（陡坡岩石、緩處草地、高處溝槽才有雪），三者都用 nearest 取樣的像素貼圖與 triplanar 投影；山腳延伸到海面以下。
   - 高度函數仍放在 `terrain-profile.js`，山體生成仍在 `fjord.ts`（依 AGENTS 峽灣模組規則）。
2. **大氣透視。** 遠山更藍、對比更低，至少拉出三層剪影。需改用依距離／高度的霧，霧色與天空一致。這是成本最低、效果最大的單項改善。
3. **水色層次。** 深處鈷藍，淺灘與島邊綠松色，看得到水下沙石。
   - 做法：淺水區半透明，下方放海床網格，以深度差（Beer–Lambert）計算吸收；碼頭樁與岩石周圍加深度交界泡沫。
   - 船隻晃動與海面 shader 共用同一個波浪函數（JS 與 GLSL 各一份、以測試確保一致），讓船真的隨浪起伏。
4. **聚落構圖。** 聚落位於低平小島與岩礁上，木橋相連，水邊有高腳漁屋。可用紅、黃木板牆的高腳漁屋，與現有灰泥木構建築形成對比，並利用水面倒影構圖。與 `architecture.ts`／`kit.ts` 建築套件相容。
5. **瀑布與飛鳥。** 瀑布用捲動貼圖 + 水霧粒子；海鷗用精靈群集。

## 5. 架構建議

- **場景配置資料化。** 建築與道具座標目前寫死在 `architecture.ts`、`environment.ts`，碰撞另外手動對齊；上一輪審查的西區不可達、穿過木箱都源於此。建議改為一份配置資料：每筆記錄包含物件類型、位置與旋轉、碰撞、地面材質（供腳步聲）、是否為遮擋物。建模與 `navigation.js` 讀取同一份資料，單元測試可直接檢查禁止重疊的區域。
- **地面高度統一。** `groundHeight(x,z)` 取代 `camera.ts` 的碼頭特例，為日後階梯、坡道與 NPC 路徑預留。
- **視覺回歸。** 不取代人眼驗收，但讓驗收更輕鬆：
  - 以網址參數（如 `?t=`）固定時間與隨機種子。這仍是同一個入口，不構成第二個頁面。
  - Playwright 在固定觀景點截圖，每個 PR 產出一張對照圖供 Owner 審查。
- **真機效能數據。** 在支援的 Android Chrome 以 `EXT_disjoint_timer_query_webgl2` 讀取 GPU 時間並回報到 `window.__pixelGame`；現行 RAF p95 不是 GPU 時間。iOS 不支援此擴充，仍需其他方式量測。

## 6. 呈現方式

- **開場鏡頭。** 參考作品以遊戲世界本身作為標題背景（景深 + 粒子 + 標題）。建議做 3～4 秒、可跳過的鏡頭運動：從峽灣高空全景俯衝到斜角視角。這是遊戲內鏡頭，不是 landing page，不違反 ADR-0003 的直接入口決策。
- **風景模式改為「明信片」機位。** 數個精心安排的固定觀景點，加上緩慢漂移與電影感黑邊，取代單一固定點自由環視。仍不移動玩家角色，符合現行規則。
- **視角切換過場。** 改為位置與 FOV 漸變，或短暫淡入淡出，不硬切。
- **斜角鏡頭細節。** 鏡頭稍微超前移動方向；兩段縮放；限制鏡頭不拍到世界邊緣。
- **環境音。** 浪聲、海鷗、風、依地面材質（石板／木頭／沙）變化的腳步聲。素材依 [ASSET-POLICY](../ASSET-POLICY.md) 登記，優先 CC0 並附 SHA256。
- **不設強制目標的探索動機（需 Owner 另行授權）。** 可坐下並切換到明信片鏡頭的長椅、「發現的風景」手帳、有生活作息的鎮民。
